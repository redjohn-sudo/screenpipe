# Windows diagnostic harness

These are retained synthetic-fixture sources from the disposable Windows 11 cloud run on September 28, 2026. Use them only in an isolated guest: the native harness controls foreground windows, clipboard, Edge and Notepad and stops guest Edge processes. It is not a host-desktop background tool.

`run-mode.ps1` is the final retained native input/sampler source. `poll-db.ts` records when frame rows are first observed. `fixture-a.html` and `fixture-b.html` contain public synthetic row markers. Paths retain the original guest layout and the localhost API key is replaced with a placeholder. The final navigation helper was corrected after the original Automatic navigation case failed; that original case remains invalid in the results. Continuous-scroll input and sampling are reported independently.

The historical guest `analyze.ts` divides CPU by four and includes descendants. It must not be reused as authoritative two-core or recorder-only analysis. The independent audit below uses explicit logical CPU count and selects only the recorder PID.

```sh
python3 audit-metrics.py /absolute/path/to/downloaded-evidence 4
python3 audit-pixels.py /absolute/path/to/downloaded-evidence
python3 normalize-row-audit.py /absolute/path/to/downloaded-evidence
```

The evidence root must contain `evidence-extracted/raw/mode-*/cases.json`, per-case `samples/*.json`, stopped database backups under `evidence-extracted/evidence/db-backups`, and `ocr.jsonl`. The OCR file is generated by the sibling `Ocr.swift` tool over every retained image; its `path` names end in `<mode>-frame-<id>.jpg`. The pixel auditor uses strict row-ID matching. The supplementary normalizer changes only a standalone letter O after “row” to 0. It is labeled separately and does not replace the strict results.

CPU is the delta between first and last per-process counters strictly inside the active interval. Working-set peak is the maximum active sample, distinct from the process lifetime peak. The gap metric is between active saved frames; quiet-tail first observation is only an upper bound when the first poll already contains the frame. Neither CPU nor saved screenshots measure foreground input-to-display latency.

The first two-core run used a different blocking sampler, stretched idle/quiet durations and omitted per-process counters. It is retained as a protocol deviation, separate from the correction run using this pinned harness. Do not combine its process-family CPU with recorder-only figures.
